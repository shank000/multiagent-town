# 模型吞吐与自适应时间治理

## 目标

时间治理器保证“模型完成一次认知所需的现实时间”不会被误写成居民已经经历的虚拟社会时间。它同时服务本地 Ollama、远程 API、自定义 Provider 与确定性 Mock，并保持已加载世界的时钟同步。

## 五层闭环

### 1. 推理工作量控制

- 高频行动、对话与规划使用 small tier，深度日记反思使用 large tier；正式研究的模型路由在实验开始前固定。
- 行动、对话、计划与日记采用有界 JSON Schema，输出预算与任务结构相匹配。
- 高频任务显式关闭模型隐式思考；日记反思按研究配置决定是否启用推理。
- Ollama 使用 `keep_alive` 保持权重驻留，并以请求级 `num_ctx` 固定上下文条件。
- 行动提示为当前现场、家庭、作息目标与玩家指令目标提供富对象信息；远处可达对象保留 `id/name`。真实模型只接收一份语义上下文，Mock 使用独立机器上下文维持确定性。

### 2. 服务能力测量

网关以最近 120 个成功的非后台请求形成滚动窗口，并记录：

- provider 原生生成 token/s；
- 输入/输出 token、端到端有效 token/s；
- P50/P90 请求时延与对话 P90；
- P90 排队等待；
- 活跃/排队请求的优先级、范围和最老等待时间；
- 当前 Provider、模型层级与样本置信度。

Ollama 的 `load_duration`、`prompt_eval_duration`、`eval_duration` 和 `total_duration` 与应用墙钟共同参与估算；API Provider 使用完整墙钟吞吐，因此网络时延自然进入容量约束。

### 3. 共享调度

请求顺序为“对话 → 行动 → 规划 → 反思 → 后台”。同优先级按世界轮询，等待任务按时长老化，队列保持有界。Ollama 单卡默认并发为 1；API 默认并发为 4。并发配置是显式实验基础设施参数，不在运行中自动改变。

### 4. 连续世界速度治理

手动档位为：

`0.05×, 0.1×, 0.2×, 0.3×, 0.5×, 0.75×, 1×, 2×, 5×, 10×, 30×, 60×`

其中 `1×` 表示每个现实秒推进 1 个游戏分钟。智能跟速使用以下约束取共同可持续档位：

1. P90 请求服务能力与最大并发决定每秒可完成的请求数；
2. 已加载居民数按行动与小时计划频率换算为每游戏分钟请求量；
3. 35% 容量预留给日记、摘要、重写与突发对话；
4. 排队或长等待触发额外降档；
5. 降速立即应用到所有已加载世界；
6. 提速要求连续三个稳定窗口，并且每次只提升一个档位。

治理窗口为 2 秒。运行方式保持为“手动”或“智能跟速”，世界工作空间重新创建时采用该工作空间的显式初始速度。

### 5. 逻辑时间完整性屏障

真实 Provider 的对话、行动、规划或反思处于生成或排队阶段时，网关报告 `cognitive_sync`。全部已加载世界在该阶段保持当前虚拟分钟，只执行以下结算：

- 接收已经完成的行动决策；
- 接收已经完成的对话轮次与摘要；
- 更新状态机和 UI；
- 继续调度模型队列。

后台摘要、记忆标注与只读统计不会单独冻结社会时间。该屏障使一次慢生成表现为现实等待，而不是人物在未形成决策时跨越数小时。

## UI 与接口

- 顶栏模型状态显示 token/s、建议上限、排队与认知同步。
- 时间状态显示手动/智能模式、设定倍率与同步状态。
- `GET /api/llm/status` 返回调度、吞吐与 `timeline` 快照。
- `POST /api/world/control {"action":"adaptive-speed"}` 开启持续智能跟速。
- `POST /api/world/control {"action":"speed","value":0.3}` 选择手动档位。
- 每次实际倍率变化写入 `timeline_speed_adjusted` 世界事件和后端结构化日志，包含模式、前后速度、原因、样本数、token/s 与 P90。

## 正式实验约束

同一因果比较中的 Provider、模型版本、量化、上下文窗口、并发、提示模板、治理策略和速度上限保持一致。所有条件组共享同一个网关与同一批次时间决策。调速轨迹作为运行基础设施数据导出，不作为人物可见信息，也不进入记忆、关系或处理变量。

模型切换、量化切换和并发探索在预实验中显式完成。正式实验期间，时间治理器只改变虚拟时钟节奏，不改变人物可访问的历史、候选集、人格、社会规则或模型身份。
