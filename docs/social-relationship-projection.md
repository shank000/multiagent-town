# 社会关系投影与会话链 v2：实现记录

> 状态：实现记录。以下内容说明当前软件操作化及其可检验边界，不是关于人类社会或 LLM 智能体的经验发现。

## 研究范围

**焦点问题**：怎样在不改变“关系记忆可见性”实验处理和伙伴选择策略的前提下，把居民间的有向关系呈现为可解释、可追溯、可比较的社会关系投影？

- 用途：实验室观察、机制审计、个案回放和可视化解释。
- 决策负责人：项目研究团队；本记录提供实现决策，不替代正式研究的预注册与效度检验。
- 范围内：合成居民的有向关系、事件证据、6+4 描述性测量、关系不对称性、网络嵌入性与近期变化。
- 范围外：将投影标签解释为人类心理测量、从 UI 标签反向驱动 agent 决策、改变正式实验的确认性指标。
- 数据伦理：仅使用模拟居民和本地事件，不处理真实个人关系数据。

## v2 分层模型

关系图按三个层次组织数据，层次之间保持可追溯而不互相替代：

1. **观察事件层**：伙伴选择、对话关系证据、馈礼和共同活动。事件 ID、方向与游戏时间构成测量来源。
2. **6+4 描述性测量层**：从指定时间窗的事件计算连续值、分子、分母、数据基础和是否可观测。没有可识别观察时使用 `null`。
3. **关系状态画像层**：保留 affection、respect 及其信任、支持、张力、暴露频率代理，用于解释当前模拟状态。画像标签是版本化筛选结果，不是居民内部持有的关系身份。

关系视图按统计层级选择视觉载体：有向测量使用 A→B 箭头，dyad 共同量使用一条 A↔B 无向线，actor 级伙伴集中度使用人物节点外环。界面不会把同一 dyad 值复制成两条有向边，也不会把行动者级 HHI 复制到该行动者的每条外向边。只有伙伴选择、尚无持久化关系状态的方向使用虚线并标为“仅行为观察”。

所有计算均由只读纯函数完成。结果不写回关系表、记忆、反思、LLM 上下文、伙伴选择策略、实验条件或确认性指标。

## 6+4 描述性测量

设当前观察窗为 \(W\)，行动者 A 在窗内的全部有效选择序列为 \(S_A\)，A 选择 B 的次数为 \(n_{A\to B}\)。每个测量同时返回 `value`、`observed`、`numerator`、`denominator` 和 `basis`。

| 家族 | 测量 | 当前操作化 | 缺失与解释边界 |
|---|---|---|---|
| 既有六项 | 伙伴回返 `partnerReturn` | A 选择 B 后，A 的下一次可观测选择仍为 B 的次数 / 存在下一次选择的 A→B 次数 | 没有可比较的后续选择时为 `null`；不单独证明关系形成 |
| 既有六项 | 关系持续性 `tiePersistence` | 相邻等长窗口中 A→B 计数的 `min(previous,current) / max(previous,current)` | 世界尚未覆盖完整前窗、两窗均无该边或选择 `all` 时为 `null`；完整双窗中仅一窗出现时为 0 |
| 既有六项 | 近因暴露 `recencyEffect` | 距所选窗口内最近关系证据或选择的时间按 7 日半衰期衰减：`2^(-elapsed/10080)`；`all` 使用全历史 | 所选窗口无该方向证据与选择时为 `null`；不是近因的因果效应估计 |
| 既有六项 | 互惠交换 `reciprocity` | 优先使用选择计数，若无选择则使用去重关系证据计数：`min(A→B,B→A) / max(A→B,B→A)` | 双向均无观察时为 `null`；机械双向写入会提高该值 |
| 既有六项 | 关系延续 `relationalCarryOver` | A 在窗内首次选择 B 后，后续全部选择中仍指向 B 的比例 | 首次选择后没有后续选择时为 `null`；属于行为延续描述量 |
| 既有六项 | 伙伴集中度 `partnerConcentration` | A 的伙伴选择份额 HHI：`Σ partnerShare²` | A 在窗内无选择时为 `null`；这是 actor 级组合量 |
| 新增四项 | 互动强度 `interactionIntensity` | 对 A→B 关系证据按 `sourceEventId` 去重，计算每周化事件率 `r`，图形值为 `1-exp(-r/4)` | 无关系证据时为 `null`；记录关系更新暴露，不覆盖全部接触与全部对话轮次 |
| 新增四项 | 关系多重性 `multiplexity` | 已观察渠道数 / 4；核心渠道为沟通、资源交换、共同活动、伙伴选择 | 四类渠道均无观察时为 `null`；`other` 保留在渠道清单但不进入四类分母 |
| 新增四项 | 依赖不对称 `dependenceAsymmetry` | `|n(A→B)/n(A→*) - n(B→A)/n(B→*)|`；有选择分母但未选择对方时分子为结构零 | 任一行动者没有有效选择分母时为 `null`；仅表示伙伴选择依赖代理 |
| 新增四项 | 网络嵌入性 `embeddedness` | 在选择与关系证据组成的无向观察网络中，去除彼此后计算共同邻居 Jaccard：`|N(A)∩N(B)| / |N(A)∪N(B)|` | 没有观察到 A—B 边时为 `null`；孤立但已观察的 dyad 为 0 |

`interactionIntensity` 的分子保留原始去重事件数，饱和值只服务于 0..1 图形编码。`multiplexity` 同时返回完整渠道清单，便于研究者区分“同一渠道反复发生”和“多个社会交换渠道并存”。`dependenceAsymmetry` 与 `embeddedness` 分别是伙伴集中和网络闭合的 dyad 级解释量，不作为额外独立因果结局。

## 时间窗与缺失语义

- 默认窗口为最近 7 个游戏日；`windowDays=all` 表示从世界起点到当前游戏时间。
- “综合关系强度”来自累计关系状态，界面固定显示为全时段且禁用窗口控件；其余 6+4 镜头遵循 7/30 日或全历史窗口。
- 有限窗口使用闭区间 `[max(0, now - windowDays×1440 + 1), now]`。持续性使用紧邻当前窗的等长前窗。
- API 接受 `windowDays=1..3650` 或 `all`；其他值返回 400。
- 当前时间之后的证据与选择不进入投影。
- `null` 表示缺少识别该测量所需的观察或分母；0 表示已有可识别观察且结果为零。界面分别显示“缺少观察”和“观察值为零”。
- affection/respect 及信任、支持、张力、暴露频率画像保持累计状态口径；`recentChange` 与 6+4 测量遵循所选时间窗。

## API 契约

### 全网摘要

`GET /api/relationships?worldId=<id>&windowDays=<1..3650|all>` 返回：

- `modelVersion: social-relations-v2`、时间窗、6+4 定义、数据质量提示与观察计数；
- 有向关系摘要及 dyad 摘要；
- 每条方向的 6+4 测量与每个 dyad 的互惠、依赖不对称和嵌入性；
- 不携带方向的逐条 `evidence`，也不在 dyad 中嵌套完整 `aToB/bToA` 或重复的方向测量对象。

该结构使 N=24—30 的全网刷新保持有界；研究者点击边后再加载详情。

### Dyad 详情

`GET /api/relationships/dyad?worldId=<id>&aId=<A>&bId=<B>&windowDays=<1..3650|all>` 返回 `social-dyad.response/v2`：

- 两位居民、双向关系画像、双向 6+4 测量与 dyad 测量；
- 按时间倒序的双向关系证据、伙伴选择事件和连续会话；
- `evidenceSummary` 的 SQL 精确总数、加载数、返回数、最早加载时间和截断状态；
- `scope.source=local_event_log` 与 `validatedRun=null`，明确本地观察数据的效度状态。

关系测量以 `[0, now]` 的完整证据历史构建累计画像，再由测量层按所选窗口切片；`evidenceSummary.totalCount` 使用同一闭区间口径的 SQL `COUNT`。这避免全局“最新若干条”截断造成旧 dyad 静默消失，同时明确提示长时段 `all` 查询的计算成本会随历史增长。

未知居民返回 404，相同的 A/B 或缺少任一 ID 返回 400。`GET /api/relationships/:id` 同样校验居民身份，并返回指定窗口的 ego 关系。

## 本地运行与正式 Replay 的边界

本地控制台从当前世界事件库读取所选时间范围内的全部 `experiment_pair_choice`。同一世界数据库内若先后启动多个实验、切换配置或复用旧数据，6+4 选择测量会形成跨本地 run 的描述性汇总；当前本地事件没有足够的 `runId/conditionId` 约束用于确认性拆分。

- w1 是“历史可见＋馈礼开启”的联合处理展示，w2 是“历史隐藏＋馈礼关闭”的零处理参考；二者不是记忆单因素对照。
- 正式推断使用 AgentSociety² Replay，并按 `runId`、`conditionId`、`protocolHash` 和 seed 独立验证与汇总。
- 馈礼形成资源交换渠道，同时是实验处理后的变量；涉及多重性、互动强度或 affection 的组间解释按馈礼条件分层。
- 本地关系图服务于机制审计、个案回放和界面解释，不替代预注册的同对重复率及结构性次要结局。

## 关系状态画像与效度边界

| ID | 候选维度 | 操作化提案 | 关键假设 | 反例或失效条件 |
|---|---|---|---|---|
| C1 | 情感亲密 | 保留有向 `affection`，范围 -1..1 | 对话摘要给出的渐进变化能表达正负情感方向 | 礼物可能是策略行为；正向变化不一定代表亲密 |
| C2 | 信任/可靠性代理 | 由带来源的互动证据中尊重与情感变化组合得到，不进入 agent 提示 | 重复的正向、可追溯互动通常增加可靠性预期 | 礼貌或地位服从会同时提高 respect，但不代表信任 |
| C3 | 尊重/地位认同 | 保留有向 `respect`，与情感亲密分开展示 | `respect` 捕捉能力评价或地位认同 | 畏惧、权力依赖和真诚尊重可能给出相同数值 |
| C4 | 工具性支持代理 | 馈礼、共同活动等证据的带方向累积值 | 资源或协作行为提供了支持信号 | 送礼可能是操控、偿还或仪式义务，而不是支持 |
| C5 | 冲突/张力代理 | 负向关系变化、负 affection/respect 的组合 | 明确负向变化比“缺少正向关系”更接近张力 | 沉默回避没有负向更新时会被漏检；争论也可能是建设性的 |
| C6 | 互动频率 | 对近期关系证据做时间衰减，测量接触强度而非情感 | 最近重复互动代表更强的关系暴露 | 高频接触可能由工作安排强制产生，与自愿关系无关 |
| C7 | 互惠与不对称 | 比较 A→B 与 B→A 的方向强度，作为 dyad 属性 | 有向差异可揭示单恋、地位差或单向依赖 | 两个方向的数据生成频率不同会制造测量不对称 |
| C8 | 探索性画像（兼容字段） | 旧版本依据投影维度生成高亲密、高支持、高尊重、高张力等筛选画像 | 兼容旧 API 与个案检索 | 新关系图不以画像着色或判定关系类型；阈值附近会跳变，画像不是社会事实或处理变量 |
| C9 | 证据与近期变化 | 保存每次更新的事件、文本、时间、变化前后值 | 可追溯记录允许研究者复核关系解释 | 上游事件摘要本身可能有偏差；缺失证据不等于零关系 |

## 假设、预测与可证伪条件

- **假设 H-P1**：方向分离能揭示被双向均值掩盖的关系不对称。
  **预测**：存在 A→B 与 B→A 强度差超过预设阈值的 dyad。
  **反证/无信息情形**：所有生产更新都机械地双向写入相同增量，此时不对称性只反映馈礼等少数规则。
- **假设 H-P2**：事件证据可把“关系值变化”连接到具体互动机制。
  **预测**：每次关系更新均能关联来源类型、游戏时间和变化前后值。
  **反证**：存在无法识别来源的生产更新，或事件与关系写入顺序导致孤儿证据。
- **假设 H-P3**：互动频率与情感亲密是可区分的。
  **预测**：可出现高频低亲密或低频高亲密的关系。
  **反例**：若频率仅由 affection 更新次数派生，两者会被算法性耦合；因此频率必须明确标为“关系更新暴露代理”。
- **假设 H-P4**：投影标签能提升个案审计效率且不改变实验结果。
  **预测**：标签只存在于只读投影与 UI；伙伴选择、Replay 和确认性指标继续读取既有字段与事件。
  **反证**：任何选择提示、处理分组或指标计算开始读取投影标签。

## 对抗性审查

- 替代解释：信任、支持和张力都是可观测行为的代理，不是心理测量真值。
- 主要混杂：共同作息导致互动机会不同；礼物处理直接增加 affection；LLM 摘要同时产生两个旧维度。
- 测量风险：对话通常双向同增，可能高估互惠；关系证据只记录改变状态的互动，不能代表全部接触。
- 防护：所有派生维度保留 `proxy` 语义；返回原始旧字段、方向、证据和算法版本；UI 标签不写回数据库；正式研究指标继续从伙伴选择 Replay 计算。
- 算法边界：组合权重、衰减周期和类型阈值是版本化的探索参数，仍需通过敏感性分析、人工编码一致性和稳健性实验验证。

## 基础依据与效度边界

- [Granovetter（1973）](https://doi.org/10.1086/225469)将关系强度讨论为时间、情感强度、亲密与互惠服务的组合，为分开记录接触频率、情感和互惠提供基础。
- [Wellman 与 Wortley（1990）](https://doi.org/10.1086/229572)表明不同关系可承载不同类型的社会支持，为将工具性支持与情感亲密分开展示提供基础。
- [Cartwright 与 Harary（1956）](https://doi.org/10.1037/h0046049)的正负、有向关系图框架，为张力、非对称与 dyad/结构层投影提供基础。
- [Coleman（1988）](https://doi.org/10.1086/228943)对义务与期待、信息渠道、规范和闭合的讨论，为保留行为证据并连接个体关系与网络结构提供基础。

这些文献只指导“哪些可观察代理值得分开记录”，不证明当前数值具备构念效度，也不为具体权重与阈值背书。当前 `trust`、`support`、`tension` 与 `frequency` 均以代理变量命名；正式报告中的效度主张须依赖后续验证。

## 决策

1. `affection` 与 `respect` 保持既有数据库字段、范围、更新夹紧和实验读取路径。
2. 新增不可变的关系证据账本；每次 `RelationshipStore.update()` 原子记录来源、游戏时间、变化前后值和可选事件 ID。
3. `social-relations-v2` 组合关系状态画像与 6+4 描述性测量；每项测量携带分子、分母、来源基础和缺失状态。
4. 关系状态画像的 `asymmetry/reciprocity` 保留为方向强度一致性的兼容字段；6+4 的互惠交换与伙伴选择依赖不对称使用独立的事件计数定义。
5. 投影按明确版本计算；类型标签使用“画像”措辞，只用于观察与筛选，不进入 LLM 上下文、伙伴选择、关系更新或研究指标。
6. 全网 API 提供去重摘要，dyad API 按需提供唯一证据时间线、选择事件和连续会话；ego API 提供指定居民的窗口化关系。
7. 每段对话拥有稳定 `conversationId`、参与者、轮次和前文；消息与事件共享事件 ID，明确记录谁对谁说。
8. 自然会话只在双方相邻时开始；正式伙伴选择轮次显式标记为安排会面。会话活跃及摘要/证据落库阶段锁定双方行动，完成后恢复原动作。
9. 会话的 `active/completed/error` 状态与摘要持久化；服务安全关闭会等待说话与摘要任务落定。

## 变更清单

- 数据层：`relationship_evidence` 表和索引；旧 `relationships` 表保持兼容。
- 存储层：关系更新的证据输入、原子写入、按居民/世界读取。
- 投影层：独立的关系画像、6+4 测量、时间窗、缺失语义、互惠/不对称、嵌入性与精确区间证据。
- 事件生产者：对话摘要、馈礼、公开活动使用同一事件 ID 关联关系证据。
- API：`/api/relationships` 返回不含嵌套证据的全网摘要；`/api/relationships/dyad` 返回边详情；`/api/relationships/:id` 返回 ego 投影；全部保留 `worldId`、窗口和居民校验。
- UI：网络图支持“社会关系/伙伴选择”切换；有向、dyad、actor 三种统计层级分别编码为箭头、无向线和节点外环；关系面板展示双向维度、连续会话与三层证据。
- 会话链：会话表、消息归属与轮次、上下文传递、活动会话快照、模拟层参与者锁和安全排空。
- 测试：旧字段兼容、证据原子性、6+4 公式与缺失值、三角/开放网络嵌入性、时间窗、摘要有界性、dyad 详情、API 世界隔离、上下文连续性、会话收尾锁与 UI 只读契约。
